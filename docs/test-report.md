首次安装实测发现：浏览器 POST 携带 `Origin: https://121.43.101.242:8443` 时，原服务只允许本地开发地址，返回 403 `Invalid CORS request`。已将线上同源地址加入服务端 `CORS_ORIGINS`，并增加携带 Origin 的回归验证。

用户首次尝试登录管理员时，登录页仍展示原框架的本地演示账号 `admin/admin123`，而线上使用随机密码的 `campusadmin`。已移除生产页面中的演示账号提示；线上确有一个待审核商品，用户可用管理员账号审核后在另一个学生账号的商品列表中验证可见性。

真实交易联调脚本为 `deploy/smoke-server.py`，使用随机生成的测试账号和商品，会在数据库中留下带“联调”字样的记录。未把管理员密码或数据库密钥输出到聊天。用户已确认另一台 Windows 设备的安装包可用，买卖双方聊天正常。用户首次注册遇到的 403 已定位为线上 Origin 未列入后端 CORS 白名单，修复后携带同一 Origin 的注册、登录以及 OPTIONS 预检均通过。

已知范围：图片使用服务器文件系统与商品 `images` 字段保存，尚无自动清理未关联图片的任务；“违规信息”页依赖审核拒绝商品，没有完整举报工单；尚未实现自动化数据库备份和独立监控。上述内容列为后续迭代，不应在答辩中描述为已完成。

密码找回目前依赖管理员线下核实身份，临时密码只在重置响应中出现一次；没有短信/邮件验证，也未强制用户首次登录修改临时密码。此次 JWT 增加密码版本校验，部署后此前已登录用户需要重新登录一次。
