# 1.0 设计理由与答辩要点

## 为什么沿用 Web 前后端并增加安装版

校园交易需要多人同时看到同一批商品和订单，因此数据应存放在公共服务器上的 MySQL。Windows exe 只负责呈现平台页面，沿用已有 Vue 界面；Spring Boot 仍在服务器处理认证和交易。这比把数据库装进每位同学电脑更容易保证数据一致，也便于浏览器与安装版共用同一账号。Electron 使用官方打包链生成安装包，远程页面关闭 Node 集成并限制导航范围。

## 为什么先修交易规则

原框架先查询商品再插入订单，两位买家同时操作时可能都看到“在售”。现在通过 `UPDATE product SET status=5 WHERE id=? AND status=1` 抢占，受影响行数只能让其中一位成功；订单插入与抢占在事务内，失败会回滚。取消时恢复在售；卖家发起交易，买卖双方各自确认，订单行锁确保并发确认时不丢状态。这几个状态可以直接画成答辩中的状态图，也能形成可重复的测试用例。

## 为什么在服务器验证权限

前端隐藏按钮不能阻止手工构造请求。商品公开列表固定只展示在售商品；非公开详情只允许卖家或管理员查看；每次 JWT 请求重新查用户状态，管理员禁用账号后旧 token 无法继续使用。生产环境数据库密码和 JWT 签名密钥由 systemd 环境文件提供，不写在前端或安装包中。

## 为什么独立使用 8443

服务器原有聊天服务占用 80/443，直接替换配置会中断已有业务。校园二手系统使用独立目录、MySQL 数据库、systemd 服务和 Nginx 8443 站点，复用已覆盖公网 IP 的 HTTPS 证书及续期机制。当前 2 核 2 GiB 服务器采用单机架构和 384 MiB 后端堆上限，适合课程演示；更大规模需再评估数据库、并发和图片存储。

## 后续如何扩展

图片从 URL 字符串改为上传服务与独立图片表；举报流程增加 `report` 表、处理状态与操作记录；补上完整的数据库集成测试、备份恢复演练、压力测试和规范化课程文档。这样每次迭代都在已经可启动、可演示的基础上增加功能。
